# Invoice Management

Invoice Management is a small invoice-processing application built for an OCR assignment. It fetches a list of synthetic Indian invoices, lets a user choose one, extracts invoice details with Tesseract OCR, and requires a human to review and approve the result before the JSON is returned.

The project runs locally and does not require a live invoice service, API key, or external JSON destination. The sample invoices are generated by the application and processed through the OCR workflow.

## What the application does

1. **Fetch invoices** displays three generated sample invoices.
2. **Choose and process** lets the user preview a selected PDF and explicitly start OCR.
3. **Review and approve** shows the recognized text and editable fields: vendor name, invoice number, vendor state, and one or more line items.
4. **Return JSON** displays the approved JSON after approval. The **Send JSON** button retrieves that result from this application's API; it does not transmit the data to an external service.

Example output:

```json
{
  "vendor_name": "Aarav Industrial Supplies",
  "invoice_no": "AIS/2026-27/113",
  "invoice_state": "Gujarat",
  "items": [
    {
      "material_description": "Stainless steel fasteners, assorted M8-M12",
      "quantity": 4.5,
      "price": 1250.0
    }
  ]
}
```

`invoice_state` is the vendor's state in India. `price` is the per-unit price in INR. Multiple materials are represented as entries in the `items` array.

## Requirements

- Python 3.10 or later
- Tesseract OCR installed on the computer
- Windows PowerShell instructions are shown below; the Python application can also run on other platforms with Tesseract installed and available

On Windows, the application checks `C:\Program Files\Tesseract-OCR\tesseract.exe`. If Tesseract is installed elsewhere, set `TESSERACT_CMD` in `.env`. Python packages are listed in [`requirements.txt`](requirements.txt). Assignment behavior and acceptance criteria are in [`PROJECT_REQUIREMENTS.md`](PROJECT_REQUIREMENTS.md).

## Setup and run on Windows

From the project directory:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Keep `SAMPLE_DATA=true` in `.env`, then start the server:

```powershell
uvicorn app.main:app --reload
```

Open <http://127.0.0.1:8000>. Click **Fetch invoices**, select an invoice, and click **Run OCR**. Review or correct the fields and line items, then click **Approve invoice**. The approved JSON appears on the page; **Send JSON** retrieves the approved result from the local application.

To stop the development server, press **Ctrl+C** in the terminal running Uvicorn.

## How it works

- [`app/synthetic.py`](app/synthetic.py) defines the Indian sample invoice data and creates the PDF files.
- [`app/main.py`](app/main.py) serves the frontend and API endpoints, retrieves source records/documents, tracks OCR jobs, and enforces the approval step.
- [`app/extraction.py`](app/extraction.py) uses PyMuPDF and Tesseract to read documents, then parses the recognized text into invoice fields and validates them with Pydantic.
- [`app/storage.py`](app/storage.py) stores invoice drafts, OCR text, and review status in SQLite at `data/invoices.db`.
- [`static/`](static/) contains the HTML, CSS, and JavaScript for the three-step user interface.
- [`tests/`](tests/) contains automated tests for parsing, storage, API behavior, OCR, and approval.

The parser uses patterns and regular expressions; it is not an AI model. OCR output is a draft and may contain errors, which is why the application displays the original document and requires human review.

## Fresh workflow behavior

When the page loads or is refreshed, it calls `POST /api/reset`. This clears the saved invoice rows and in-memory OCR jobs so the user starts fresh. This is appropriate for the single-user assignment workflow, but it affects the app's shared database and is not suitable for multiple users working at once.

## Tests

Run the test suite from the project directory:

```powershell
python -m unittest discover -v
```

## Current scope

- The included invoices are synthetic; no production invoice data or external invoice service is configured.
- The **Send JSON** button returns the approved JSON within this app. Connecting a downstream system would require a destination API and its expected request format.
- The application has no user login or access control. Run it locally for this assignment; do not expose it to untrusted users.
- OCR and parsing accuracy depends on document quality and layout. The reviewer should verify all extracted fields before approval.
- Sample and OCR data are stored locally in SQLite. The page refresh reset clears the shared local records.
